## 12:40

`bench.py` said why each rule exists in its own docstrings, which is what
`notes/` is for. The prose moved unchanged into `notes/harness.md` and each
function kept a one-line docstring. `load15()` wrapped `os.getloadavg()[2]` with
no caller outside `before()`, so it is inlined; `contention()` stays a named
function because the open load-gate proposal in `BUGS.md` refers to it by name.

## 14:10

A measured run took three hand-assembled steps and a hand-typed core list.
`bench.claim()` does all of it. It builds the fingerprint binary and the
variants, prints how idle the pinned cores are, then re-executes the runner under
`sudo chrt -f 80 taskset -c <cores>` and exits with its status. The measured pass
returns from `claim()` immediately, so it never compiles.

The cores come from each measurement's own config rather than from the command
line, which retires the documented `-c 2,3` that names cores this box does not
have.

Verified rather than assumed: the escalated pass reports euid 0, affinity [0, 1]
and scheduler policy 1. `dist/fingerprint` came out owned by `onvos`, which is
the evidence that every compile stayed unprivileged and `go` stayed at 1.27.1
instead of dropping to the system 1.19.8.

## 17:20

Three read-only studies swept the tooling: the four runners, the harness core,
and the make layer.

The make layer was the worst of it. Every measurement Makefile redefined all six
targets while `measurement.mk` defined them too, so including it printed 22
overriding-recipe warning pairs. The stubs are gone. `prepare`, `lint` and
`clean` are optional no-ops, and `.DEFAULT` raises for a missing `build`, `test`
or `bench`, because a `.PHONY` target with no recipe reports "Nothing to be done"
and exits 0. `help` went too: nothing invoked it and it had already drifted,
claiming `bench` builds the variants when 02's passed `--no-build`.

The runner study talked me out of every merge but one, and that is worth more
than the merge. The RESULT-line parse looks identical in all four and each
wrapper differs on what happens when there is no result. The warm-up and reps
loop would need a run callable, a field-selection rule, a per-rep checksum policy
and a return shape, which is a framework. The harness study found `bench.py`
cannot reach its own one-screen rule by pruning at all: every function has a
caller, and all safe cuts together leave about 139 lines. The rule is
aspirational and the file now says so.

Two studies independently found measurement 03 hand-rolling the checksum gate,
skipping `bench.gate`'s refusal of a gate over fewer than two rows.

## 18:50

Two rules the repository states and did not keep.

`BUGS.md` recorded that the gate agreed on a checksum which never reached
`results/`. `gate()` now returns the value it accepted, each runner collects one
per swept point, and `record()` writes a `checksums:` block. A claim that two
runs did identical work is checkable from the two files instead of from a console
nobody kept.

`CLAUDE.md` asks for toolchain versions in every result file, and zero of eight
carried them. A reading taken inside `record()` would have been wrong as well as
missing: that code runs as root, where `GOTOOLCHAIN` cannot resolve and `go` is
go1.19.8. `claim()` writes the reading to `dist/toolchains.json` while still
unprivileged, and `record()` copies it in, so the recorded versions are the ones
that built the binaries.

02's `bench` dropped `--no-build`. It only ever built the fingerprint binary, so
editing a variant and running `make bench` measured the old one in silence.

01's `--quick` wrote a full result file, because it never returned before
`record()` the way the other three do. One of my own test runs produced such a
file; it was untracked and is deleted, and the two real results are untouched.
01's `make test` now runs the quick pass, so the gate runs there at all.

## 19:00

No measured run fired today. The pinned cores sat between 22% and 41% busy with
the 15-minute load between 1.21 and 1.50 against a 1.6 limit, so a run would have
been stamped `verified` while the cores were a quarter busy. That is the gap
`BUGS.md` already describes, and firing a baseline into it would have been the
one mistake this harness exists to prevent.
